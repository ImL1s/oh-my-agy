# Repository Guidelines

## Project Structure & Module Organization

| Path | Role |
|------|------|
| `bin/oma.ts` | CLI entry (`oma` / `omy`) — dual path: structured CLI vs legacy magic / pass-through |
| `src/cli/` | argv parse, managed invocation (exact_env), services wiring |
| `src/hooks/` | PreInvocation / Stop (Antigravity lifecycle) |
| `src/continuation/` | SessionLocator, SessionAggregate, ProgressOracle |
| `src/autopilot/` | Durable Autopilot FSM |
| `src/team/` | Team/tmux/worktree/recovery-fork |
| `src/enforcer.ts` | Legacy todo.json continuation + circuit breaker (no destructive git) |
| `src/runtime/` | locks, atomic writes, process, state-root |
| `tests/**` | Unit tests (`npm run test:unit`) |
| `e2e/**` | Legacy CLI e2e (`npm run test:e2e`); `mocks/agy` replaces host CLI |
| `hooks.json` / `plugin.json` | Package plugin surface |
| `.agents/hooks.json` | Optional project-local hooks (relative `../dist/src/hooks/*`) |
| `dist/` | Generated by `tsc` — do not edit |
| `assets/` | README mascot |

Runtime-only (gitignored): `.omx/`, `.agy/`, `.agy_sandbox_*`, `node_modules/`.

Architecture notes: `PROJECT.md`, `DESIGN.md`, `TEST_INFRA.md`. User-facing overview: `README.md`.

## Build, Test, and Development Commands

```bash
npm ci                 # exact lockfile deps
npm run build          # tsc → dist/
npm run test:unit      # 108 unit tests (runInBand)
npm run test:e2e       # 63 e2e tests (runInBand)
node dist/bin/oma.js --help
```

Managed mode (exact_env): `oma ralph -- "<task>"` — note the `--` delimiter.  
Legacy magic / pass-through strip managed binding env; see README dual-path table.

## Coding Style & Naming Conventions

Strict TypeScript, two-space indent, semicolons, single quotes.  
`PascalCase` types/classes; `camelCase` functions/vars; `UPPER_SNAKE_CASE` constants.  
Comments in Traditional Chinese with design-mapping notes when porting concepts from OMC/OMX/OmO.  
Never `exec` external commands — only `spawn` / `spawnSync` with argv arrays.  
Static check: `npm run build` (no separate formatter/linter configured).

## Testing Guidelines

- Unit: `tests/**/*.spec.ts` via `jest.unit.config.js`
- E2E: `e2e/**/*.spec.ts` via `jest.config.js`; case names `TC-T<tier>-<number>`
- Prefer condition waits over fixed sleeps; sandbox via `e2e/helper.ts`
- No coverage gate; full unit + e2e green is the bar before release claims

## Commit & Pull Request Guidelines

Conventional Commits preferred (`feat:`, `fix:`, `docs:`, `chore:`).  
PRs: user-visible behavior, validation commands + results, notes for hooks/binding/spawn/locking changes.

## Safety

- Circuit breaker must never run `git reset --hard` / `git clean -fd`
- Managed binding env: `OMA_SESSION_ID`, `OMA_LAUNCH_NONCE`, `OMA_INVOCATION_GENERATION`
- Launch nonce is capability material — debug logs use fingerprint only
